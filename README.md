# Project Backend — Tic-Tac-Toe 

## 📖 О проекте

Проект состоит из трёх частей, выполненных последовательно в рамках обучения в «Школе 21»:

1. **Tic-Tac-Toe (Бэкенд 03)** — создание веб-приложения для игры в «Крестики-Нолики» на Java с использованием Spring (in-memory хранилище, одиночная игра с компьютером).
2. **Backend 04** — добавление **PostgreSQL**, **Basic-авторизации** (логин/пароль) и поддержки **мультиплеера** (игра между двумя игроками).
3. **Backend 05** — замена Basic-авторизации на **JWT**, добавление **истории игр** и **таблицы лидеров**.

---

## 🎯 Общая цель

- Научиться создавать веб-приложения на **Java** с использованием **Spring**
- Освоить многослойную архитектуру (web, domain, datasource, di)
- Реализовать игровой алгоритм **«Минимакс»** для игры в «Крестики-Нолики»
- Подключить **PostgreSQL** для хранения данных
- Реализовать **авторизацию** (Basic → JWT)
- Добавить поддержку **игры между двумя игроками**
- Добавить **историю игр** и **таблицу лидеров**

### Задание 2. Добавление авторизации (Basic Auth)

#### Модель пользователя
- Добавлен пользователь с полями:
- `UUID` — уникальный идентификатор
- `login` — логин пользователя
- `password` — пароль (хранится в зашифрованном виде — BCrypt)

#### Регистрация и авторизация
- Создана модель `SignUpRequest` (логин + пароль)
- Реализован **сервис авторизации**:
- `register()` — регистрация нового пользователя
- `authenticate()` — авторизация по логину/паролю из заголовка `Authorization: Basic base64(login:password)`, возвращает `UUID` пользователя

#### Контроллер авторизации
- **POST /auth/signup** — регистрация пользователя
- **POST /auth/login** — авторизация пользователя

#### AuthFilter
- Создан фильтр, наследующий `GenericFilterBean`
- В методе `doFilter()`:
- Извлекается заголовок `Authorization`
- Парсится и валидируется логин/пароль (Base64)
- При успехе — запрос выполняется
- При ошибке — возвращается статус **401 Unauthorized**

#### Spring Security Configuration
- Настроена цепочка фильтров (`SecurityFilterChain`)
- Доступ без авторизации разрешён только для эндпоинтов:
- `/auth/signup`
- `/auth/login`
- Все остальные эндпоинты требуют авторизации
- Добавлен `AuthFilter` в цепочку фильтров

### Задание 3. Логика игры между двумя игроками

#### Расширение состояний игры
Добавлены новые состояния для текущей игры:
- `WAITING_PLAYERS` — ожидание подключения второго игрока
- `PLAYER_TURN` — ход игрока с указанным UUID
- `DRAW` — ничья
- `PLAYER_WIN` — победа игрока с указанным UUID

#### Информация о значках
- В игру добавлена информация о том, каким значком (`X` или `O`) ходит каждый игрок

#### Улучшение алгоритма определения окончания игры
- Алгоритм проверки окончания игры теперь учитывает все состояния:
- Победа (горизонталь, вертикаль, диагональ)
- Ничья (заполнено всё поле)
- Продолжение игры

#### Новые эндпоинты

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/game/create` | Создание новой игры (с компьютером или ожиданием игрока) |
| GET | `/game/available` | Получение списка доступных для подключения игр |
| POST | `/game/join/{gameId}` | Подключение пользователя к существующей игре |
| PUT | `/game/{gameId}` | Обновление игры (ход игрока) с учётом PvP или PvE |
| GET | `/game/{gameId}` | Получение текущего состояния игры |
| GET | `/user/{userId}` | Получение информации о пользователе по UUID |

#### Логика PvP и PvE
- **PvP** (Player vs Player): два игрока ходят по очереди
- **PvE** (Player vs Computer): игрок ходит, компьютер отвечает алгоритмом «Минимакс»
- В зависимости от режима игры выбирается разная логика обработки хода

## 🧩 Часть 3. Backend 05 — JWT, История игр и Таблица лидеров

### Задание 1. Замена Basic-авторизации на JWT

#### Роли и безопасность
- Добавлена роль **USER** (наследование от `GrantedAuthority`)
- Реализована поддержка ролей на всех слоях
- Добавлен список ролей у пользователей

#### Модели для JWT
- `JwtRequest` — логин и пароль
- `JwtResponse` — тип, `accessToken`, `refreshToken`
- `RefreshJwtRequest` — `refreshToken`

#### JwtProvider
Реализован класс с методами:
- Генерация **accessToken** с сохранением UUID и ролей в `claims`
- Генерация **refreshToken** с сохранением UUID в `claims`
- Валидация **accessToken** и **refreshToken**
- Получение `claims` из токена

#### JwtAuthentication
- Реализована кастомная аутентификация (наследование от `Authentication`)
- `getAuthorities()` — возвращает роли
- `getPrincipal()` и `getName()` — возвращают UUID
- Добавлено поле для факта авторизации

#### JwtUtil
- Метод создания `JwtAuthentication` по `claims`

#### Обновление сервиса авторизации
- Авторизация принимает `JwtRequest`, возвращает `JwtResponse`
- Метод обновления `accessToken` по `refreshToken`
- Метод обновления `refreshToken`
- Метод получения `JwtAuthentication`

#### Обновление контроллера
- **POST /auth/login** — авторизация пользователя (возвращает JWT)
- **POST /auth/access** — обновление accessToken
- **POST /auth/refresh** — обновление refreshToken
- **GET /auth/me** — получение информации о пользователе по accessToken

#### AuthFilter (обновлён)
- Извлечение токена из заголовка `Authorization: Bearer {accessToken}`
- Валидация токена через `JwtProvider`
- Получение `claims` и создание `JwtAuthentication`
- Установка авторизации через `SecurityContextHolder`

#### Spring Configuration (обновлён)
- Доступ без авторизации к эндпоинтам обновления токенов
- Настройка фильтров и цепочки безопасности
